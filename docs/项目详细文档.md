# C IDE — 类 C 语言集成开发环境 完整文档

## 一、项目概述

C IDE 是一个基于 Electron 的桌面端类 C 语言编程集成开发环境（Windows .exe）。外观仿 VS Code 暗色风格，内置自研 Python 编译器，支持语法高亮、实时错误检测、编译运行。

**核心能力**：
- 打开本地文件夹，侧栏浏览文件树
- 多标签页代码编辑，支持 Ctrl+S 保存到磁盘
- 按下 F5 一键编译 + 链接 + 运行，看到程序输出
- 可按文件选择启用 C 语法高亮和实时错误下划线
- 启动时自动恢复上次工作区

**技术组合**：Electron（桌面外壳） + React（界面） + CodeMirror 6（编辑器） + Python（编译器/扫描器）

## 四、主进程详解（src/main/index.ts）

主进程是 Electron 应用的"后台"，拥有完整的 Node.js 能力。

### 4.1 窗口创建

```
app.whenReady() → createWindow()
  ├─ new BrowserWindow (1200×800, 暗色背景)
  ├─ 设置菜单栏（文件/编辑/运行）
  ├─ 拦截 F12 和 Ctrl+Shift+I（禁用开发者工具）
  ├─ 监听 close 事件（有未保存修改时弹确认框）
  └─ 加载渲染进程页面
```

窗口使用 `show: false` 创建，等 `ready-to-show` 事件后再显示，避免白屏闪烁。

### 4.2 菜单结构

| 菜单 | 项目 | 快捷键 | 功能 |
|------|------|--------|------|
| 文件 | 打开文件夹... | Ctrl+K Ctrl+O | 原生文件夹选择对话框 |
| 文件 | 保存 | Ctrl+S | 保存当前文件 |
| 文件 | 退出 | - | 关闭应用 |
| 编辑 | 撤销/重做/剪切/复制/粘贴 | 标准快捷键 | 编辑器内置操作 |
| 运行 | 编译生成 .s | F7 | Python 编译器 → 汇编文件 |
| 运行 | 链接并运行 | F5 | 编译 + gcc 链接 + 运行 exe |

### 4.3 文件操作

**扫描目录**（`scanDirectory`）：
- 递归遍历文件夹，跳过 `.` 开头文件和 `node_modules`
- 文件夹排在文件前面，同类型按名称字母排序
- 返回 `FileNode` 树形结构，`id` 就是文件/文件夹的绝对路径

**编码检测**（`detectAndDecode`）：
- 先检查文件开头的 BOM 字节（`EF BB BF` → UTF-8，`FF FE` → UTF-16 LE，`FE FF` → UTF-16 BE）
- 无 BOM 时尝试 UTF-8 解码，如果出现替换字符 `�` 则说明不是 UTF-8
- 回退到 GBK（中文 Windows 最常见的本地编码）
- 最后兜底用 Latin-1（逐字节映射，不会失败）

### 4.4 IPC 通道一览

| IPC 通道 | 方向 | 功能 |
|----------|------|------|
| `open-folder` | 渲染→主 | 弹出文件夹选择框，扫描目录树，保存工作区路径 |
| `get-last-workspace` | 渲染→主 | 读取上次工作区路径，重新扫描目录 |
| `read-file` | 渲染→主 | 读取文件，自动检测编码 |
| `read-file-with-encoding` | 渲染→主 | 以指定编码读取文件 |
| `write-file` | 渲染→主 | 写入文件（UTF-8） |
| `scan-folder` | 渲染→主 | 重新扫描指定目录 |
| `scan-code` | 渲染→主 | 把代码文本发给 Python 扫描器，返回 tokens 和 errors |
| `compile-file` | 渲染→主 | 调用 Python 编译器生成 .s 汇编文件 |
| `link-and-run` | 渲染→主 | 编译 + gcc 链接 + 启动 exe |
| `watch-folder` | 渲染→主 | 启动文件夹监听（外部变更通知） |
| `stop-watch` | 渲染→主 | 停止文件夹监听 |
| `set-dirty-state` | 渲染→主 | 同步是否有未保存文件（用于关闭确认） |
| `confirm-quit` | 渲染→主 | 确认退出（保存完成后调用） |

主进程也通过 `webContents.send` 向渲染进程发送菜单点击事件：
`menu-open-folder`、`menu-save`、`menu-compile`、`menu-link-run`、`save-all-and-close`、`file-changed`

### 4.5 Python 子进程管理

为了高性能的词法扫描，主进程维护一个常驻的 Python 子进程：

```
首次 scan-code 请求
  → spawn('python', ['scanner_bridge.py'])
  → 读取 stdout 逐行解析 JSON
  → 后续请求复用同一进程（不重启 Python）

应用退出时
  → 发送 {"action": "exit"} 给 Python
  → kill 子进程
```

每行 stdin 输入一个 JSON 请求，每行 stdout 输出一个 JSON 响应。这种"行协议"避免了复杂的进程间通信框架，足够简单可靠。

### 4.6 工作区持久化

- 打开文件夹时，路径写入 `%APPDATA%/C IDE/workspace.json`
- 应用启动时调用 `get-last-workspace`，如果目录仍存在则自动恢复
- 目录被删除或移动则静默跳过，不弹错误

## 五、预加载脚本详解（src/preload/index.ts）

预加载脚本在主进程和渲染进程之间架设安全桥梁。通过 `contextBridge.exposeInMainWorld`，只暴露有限的方法给渲染进程的 `window.electronAPI`。

**暴露的 API**：
- 文件操作：`openFolder`、`readFile`、`readFileWithEncoding`、`writeFile`、`scanFolder`
- 编译器：`scanCode`、`compileFile`、`linkAndRun`
- 工作区：`getLastWorkspace`
- 状态同步：`setDirtyState`、`confirmQuit`
- 文件监听：`watchFolder`、`stopWatch`
- 菜单事件监听：`onMenuOpenFolder`、`onMenuSave`、`onMenuCompile`、`onMenuLinkRun`、`onSaveAllAndClose`、`onFileChanged`

每个事件监听方法返回一个取消订阅函数，方便 React 的 `useEffect` 清理。

## 七、状态管理（Zustand Store）

所有应用状态集中在一个 Zustand store 中（`src/store/useEditorStore.ts`）。

### 7.1 核心状态

| 字段 | 类型 | 说明 |
|------|------|------|
| `folderPath` | `string \| null` | 当前打开的文件夹绝对路径 |
| `fileTree` | `FileNode[]` | 文件树（从主进程扫描获得） |
| `expandedFolders` | `Set<string>` | 文件树中已展开的文件夹 ID |
| `openTabs` | `OpenTab[]` | 已打开的标签页列表 |
| `activeTabId` | `string \| null` | 当前活动标签的文件路径 |
| `fileContents` | `Record<string, string>` | 每个文件的内存内容缓存 |
| `fileEncodings` | `Record<string, string>` | 每个文件的编码记录 |
| `fileLanguageModes` | `Record<string, 'c' \| 'text'>` | 每个文件的语法高亮模式 |
| `cursorPosition` | `{line, column}` | 当前光标位置（1-based） |

### 7.2 关键操作

**openFile**：检查是否已打开 → 未打开则加入 `openTabs` → 异步调用 `readFile` IPC 加载内容

**updateFileContent**：更新 `fileContents` → 对比 `savedContent` 判断是否脏（`isDirty`）

**saveFile**：调用 `writeFile` IPC 写入磁盘 → 更新 `savedContent` → 清除脏状态

**openFolder**：调用 `open-folder` IPC → 设置文件树和路径 → 启动文件夹监听

**restoreLastWorkspace**：调用 `get-last-workspace` IPC → 恢复上次工作区

**saveAllDirtyFiles**：遍历所有脏标签逐一保存（关闭前批量保存用）

**reopenWithEncoding**：以指定编码重新读取文件

**toggleCLanguage**：切换单个文件的 C/文本 模式

### 7.3 数据流示例：用户打开文件

```
用户点击文件树中的 main.c
  → FileTree.onClick → openFile("D:/project/main.c")
  → store.openFile()
    → 检查 openTabs，未打开
    → 添加 tab: { id: "D:/project/main.c", name: "main.c", isDirty: false }
    → 设置 activeTabId = "D:/project/main.c"
    → 异步调用 window.electronAPI.readFile("D:/project/main.c")
      → IPC → 主进程 → readFileSync → detectAndDecode
      → 返回 { content: "int main()...", encoding: "UTF-8" }
    → 更新 fileContents 和 fileEncodings
  → EditorPanel 检测到 activeTabId 变化
  → 渲染 CodeEditor key="D:/project/main.c"
  → CodeMirror 显示文件内容
```

## 八、Python 编译器详解（compiler/）

### 8.1 编译器流水线

```
源代码 (.c)
  │
  ▼
scanner.py (词法分析)
  → Token 序列 (类型, 文本, 行号)
  │
  ▼
parser.py (语法分析)
  → AST 抽象语法树
  │
  ▼
semantic.py (语义分析)
  → 类型检查、作用域分析
  │
  ▼
codegen.py (代码生成)
  → x86-64 汇编 (.s)
  │
  ▼
gcc (汇编 + 链接)
  → .exe 可执行文件
```

### 8.2 scanner_bridge.py（IDE 桥接进程）

这是连接 IDE 和编译器的关键组件。它是一个常驻的 Python 进程，通过 stdin/stdout 的 JSON 行协议与 Node.js 主进程通信。

```
协议格式：
← {"code": "int main() { return 0; }"}
→ {"tokens": [{"type": 102, "text": "int", "from": 0, "to": 3, "line": 1}, ...],
   "errors": [{"from": 0, "to": 30, "line": 1, "message": "缺少分号 ;"}]}
```

**工作流程**：
1. 收到 code → 调用 `LexialAnalyzer(code)` 做词法分析
2. 把 Scanner Token 转换为 Parser Token 格式
3. 调用 `ErrorParser` 做容错语法分析（不抛异常，收集所有错误）
4. 合并词法错误和语法错误
5. 把行号映射为字符偏移（`line_to_offset`），方便前端定位
6. 返回 JSON

**容错设计**：使用 `ErrorParser` 而非 `Parser`。`ErrorParser` 在遇到错误后会尝试同步恢复（跳过部分 token 直到分号或花括号），从而能在一次扫描中报告多个错误，不会因第一个错误就中断。

### 8.3 错误码对照

| 错误码 | 类型 | 含义 |
|--------|------|------|
| 101 | 词法 | 非法字符 |
| 102 | 词法 | 无效 Token |
| 103 | 词法 | 注释未闭合（缺少 */） |
| 104 | 词法 | 字符常量未闭合（缺少 '） |
| 105 | 词法 | 字符串未闭合（缺少 "） |
| 201 | 语法 | 缺少标识符 |
| 202 | 语法 | 缺少分号 ; |
| 203 | 语法 | 多余的 } |
| 204 | 语法 | 缺少 { |
| 205 | 语法 | 缺少 } |
| 206 | 语法 | 多余的 ) |
| 207 | 语法 | 缺少 ( |
| 208 | 语法 | 缺少 ) |
| 210 | 语法 | 赋值左侧必须是变量 |
| 211 | 语法 | 缺少操作数 |
| 212 | 语法 | do-while 缺少 while |

## 九、C 语法高亮与错误检测（src/language/）

### 9.1 types.ts — Token 类型与配色

定义了 `TokenType` 枚举（值与 scanner.py 中的枚举一致）和 `tokenColor()` 配色函数。

| Token 类别 | 颜色 | 色值 |
|-----------|------|------|
| 关键字 (int, return, if...) | 蓝色 | `#569CD6` |
| 数字 (整数/浮点) | 浅绿 | `#B5CEA8` |
| 字符串/字符 | 橙色 | `#CE9178` |
| 注释 (//, /* */) | 灰绿 | `#6A9955` |
| 标识符（变量名） | 浅蓝 | `#9CDCFE` |
| 函数名（标识符 + '('） | 黄色 | `#DCDCAA` |

函数名检测：遍历 token 列表，如果第 i 个是 IDENTIFIER 且第 i+1 个是 LPAREN，则第 i 个被标记为函数名。

### 9.2 cHighlight.ts — CodeMirror 扩展

这是"前端 → Python 扫描器"的桥梁。它由两部分组成：

**高亮部分**（ViewPlugin）：
- 文档变更 300ms 后调用 `window.electronAPI.scanCode(code)`
- 拿到 tokens 后，用 `RangeSetBuilder` 构建 `Decoration` 集合
- 每个 token 按类型着色，通过 `Decoration.mark({ attributes: { style: 'color: ...' } })` 实现
- 通过 `StateEffect` 和 `StateField` 将 decorations 注入编辑器

**错误检测部分**（Linter）：
- 使用 `@codemirror/lint` 的 `linter()` 扩展
- 从 `scanCode` 返回的 errors 构造 `Diagnostic[]`
- 每个 diagnostic 包含起止位置、错误消息、严重级别 `'error'`
- CodeMirror 自动在错误位置显示红色波浪下划线，悬停显示错误消息

**防抖策略**：ViewPlugin 收到文档变更后清除旧 timer，设新 timer 300ms。300ms 内持续输入则不断重置，停止 300ms 后才真正发送 IPC。这避免了每次按键都启动 Python 扫描。

## 十、编译运行流程

### 编译生成 .s（F7）

```
F7 按下
  → 主进程发 menu-compile 事件给渲染进程
  → App.tsx 收到 → saveFile(activeTabId) 保存当前文件
  → 调用 compileFile IPC，传文件路径
  → 主进程: python mycompiler.py <源文件> -S -o <同名.s>
  → 返回结果 → alert 显示
```

### 链接并运行（F5）

```
F5 按下
  → 同上先保存文件
  → 调用 linkAndRun IPC
  → 主进程:
     1. python mycompiler.py <源文件> -S -o <同名.s>  (编译)
     2. gcc <同名.s> -o <同名.exe>                    (链接)
     3. start cmd /c "cd <目录> && <exe> && pause"   (运行)
  → exe 在新 cmd 窗口运行，结束后显示"按任意键关闭"
  → 按任意键后窗口关闭
```

## 十二、关键设计决策

| 决策 | 原因 |
|------|------|
| 用 `EditorView.theme` 而非 CSS 处理滚动 | CSS Modules 对 CodeMirror 内部元素选择器优先级不够，theme 直接注入 style 标签 |
| 用 `fs.watch` 而非 chokidar | chokidar 体积大（~2MB JS 解析），Node 内置 `fs.watch` 无额外开销 |
| 每个文件独立 CodeMirror 实例（`key={fileId}`） | 保留独立的撤销历史、滚动位置，切换标签不串状态 |
| `show: false` + `ready-to-show` | 避免窗口先显示白屏再加载内容的闪烁 |
| Python 常驻进程（不每次重启） | Python 冷启动 ~200ms，常驻后每次扫描 <5ms |
| `ErrorParser` 而非 `Parser` 做 lint | `ErrorParser` 是容错解析器，错误后能同步恢复，一次扫描报告多个错误 |
| C 模式按文件可选（默认关闭） | 纯文本编辑不需要启动 Python，省资源；用户手动开启才用 |
